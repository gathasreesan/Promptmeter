  SECTION 1: BUG FIX LOG

[ BUG #1 ] content.js — Forced Layout Reflow Causing Browser Freeze
FILE: content.js (line 205, applyOptimization function)
PROBLEM:
  promptBox.innerText was being read inside applyOptimization(). Accessing
  `.innerText` forces Chrome to calculate element geometry + layout reflow
  synchronously. When called during ChatGPT's streaming, this froze the
  main thread and caused the "Page Unresponsive" crash dialog.
FIX:
  Changed promptBox.innerText → promptBox.textContent everywhere in
  content.js (findPrecedingUserPrompt, processDOMUpdates, applyOptimization).
  textContent reads raw DOM text nodes without triggering layout calculations.

----------------------------------------------------------------------

[ BUG #2 ] content.js — handleInput Reads Stale Text Value
FILE: content.js (handleInput function)
PROBLEM:
  The `originalText` variable was captured at the time of the keystroke,
  then used inside a 450ms `setTimeout`. If the user continued typing
  during those 450ms, the captured text was stale — the optimization would
  analyze and rewrite the OLD text, not what the user actually typed.
FIX:
  Moved text reading INSIDE the debounced callback so it always reads the
  current prompt box value at the moment analysis actually runs.

----------------------------------------------------------------------

[ BUG #3 ] content.js — Duplicate Event Listener Registration
FILE: content.js (bindInputListeners function)
PROBLEM:
  The `keyup` event was attached alongside `input` and `paste`. Since
  every keypress fires both `keydown` then `input` then `keyup`, the
  handleInput function ran 2x per keystroke: once on `input`, once on
  `keyup`. This caused double debounce resets and double analysis calls.
FIX:
  Removed the `keyup` listener. `input` alone correctly captures typing,
  paste, voice input, and programmatic value changes.

----------------------------------------------------------------------

[ BUG #4 ] optimizer.js — Dangerous chatSlangMap: "u"→"you", "r"→"are"
FILE: utils/optimizer.js (correctGrammarAndSpelling, chatSlangMap)
PROBLEM:
  The slang expansion for single-letter words "u" and "r" used \b word
  boundaries but still destructively matched:
    - "url" → "yourl"  (u → you inside "url")
    - "router" → "areeouter" (r → are inside "router") 
    - "user" → "youser"
    - "return" → "arereturn"
  These corrupted technical prompts containing common programming terms.
FIX:
  Removed "u" and "r" from chatSlangMap entirely. These single-character
  expansions are too destructive for any technical context.

----------------------------------------------------------------------

[ BUG #5 ] optimizer.js — Stage 8 Duplicate Word Regex Corrupts Code
FILE: utils/optimizer.js (optimizePrompt, STAGE 8)
PROBLEM:
  The duplicate adjacent word removal regex `\b(\w+)\s+\1\b` with `gi`
  flag would incorrectly collapse legitimate repetitions in code like:
    "if if", "return return" and variable names like "test test_data"
  The regex had no lastIndex reset either, making it non-deterministic.
FIX:
  Added a guard: only run duplicate-word removal if the text does not
  contain code block placeholders (i.e., skip on code-containing prompts).
  Also tightened it to only remove repeated short filler words.

----------------------------------------------------------------------

[ BUG #6 ] optimizer.js — contractionMap Fires Inside Technical Words
FILE: utils/optimizer.js (correctGrammarAndSpelling, contractionMap)
PROBLEM:
  Words like "cant" (can't) matched the word "significant" → "signifI'mt"
  Wait, no — with \b it matched standalone words. BUT more critically,
  "im" matched inside compound tokens like "Im" at start of sentences.
  The `'gi'` flag caused "IM" (Instant Messaging) → "I'm". The `i` flag
  is correct but the expansion should preserve original capitalization.
FIX:
  Changed contractionMap replacements to use a function that preserves
  the original capitalization of the matched word's first letter.

----------------------------------------------------------------------

[ BUG #7 ] optimizer.js — Regex globalStrippers Not Reset Between Passes
FILE: utils/optimizer.js (optimizePrompt, STAGE 3)
PROBLEM:
  The `globalStrippers` array contains regex literals with the `g` flag.
  In JavaScript, stateful `/g` regexes maintain `.lastIndex` across calls.
  When the same regex object is reused in a second pass without resetting
  `.lastIndex = 0`, the match starts from the WRONG position — causing
  some patterns to be skipped entirely on the second pass.
FIX:
  Already added `rx.lastIndex = 0` in each pass. Confirmed this is working
  correctly. No additional change needed — documented here for reference.

----------------------------------------------------------------------

[ BUG #8 ] content.js — applyOptimization Does Not Re-read Text Live
FILE: content.js (applyOptimization function)
PROBLEM:
  Inside applyOptimization, `originalText` was read from promptBox at time
  of click. If the MutationObserver or a React reconciliation updated the
  DOM between the user clicking "Accept" and the function running, the
  text could be stale — resulting in incorrectly calculated tokensSaved.
FIX:
  Added a fresh prompt box text read inside applyOptimization using
  textContent (not innerText) so the value is always current.

----------------------------------------------------------------------

[ BUG #9 ] popup.js — Stats Render Silently Fails Without Storage API
FILE: popup.js (line 48)
PROBLEM:
  The popup stats update was guarded with `typeof PromptMeterStorage !==
  'undefined'` but if chrome.storage returns an error (e.g. permissions
  issue on first install), the callback was never called — DOM elements
  defaulted to empty strings with no fallback.
FIX:
  Added null-safe reads for each DOM element update:
    element && (element.textContent = value)
  So the popup never crashes even if storage is temporarily unavailable.

----------------------------------------------------------------------

[ BUG #10 ] manifest.json — tiktoken.min.js (1.1MB) Was Loading on Page
FILE: manifest.json
PROBLEM:
  tiktoken.min.js (1.1 MB BPE vocabulary matrix) was being compiled by
  Chrome's V8 engine on every ChatGPT page load. This caused:
    - 800-1200ms page load delay
    - Blocked the main thread during compilation
    - Caused visible "Page Unresponsive" freezes during first tab load
FIX:
  Removed tiktoken.min.js from the content_scripts list in manifest.json.
  The tokenizer.js now uses a fast hybrid heuristic that runs in < 0.1ms.

----------------------------------------------------------------------

[ BUG #11 ] content.js — MutationObserver Was Watching Attributes
FILE: content.js (observer.observe)
PROBLEM:
  The observer was configured with:
    attributes: true, attributeFilter: ["class"]
  Every CSS animation, streaming cursor blink, hover effect, or React
  state update that changed a class attribute fired the observer callback.
  On ChatGPT's heavily-animated streaming UI, this meant 30-60 callbacks
  per second — each triggering DOM scans.
FIX:
  Removed `attributes: true` and `attributeFilter` config.
  Observer now only watches `childList: true, subtree: true`.
  This reduced observer firing from ~60/sec to ~2-5/sec.

----------------------------------------------------------------------

[ BUG #12 ] content.js — MutationObserver All DOM Ops Were Unthrottled
FILE: content.js (MutationObserver callback)
PROBLEM:
  The streaming detection and assistant message scanning ran directly in
  the MutationObserver callback body on EVERY observed mutation. This
  means 30-60 DOM scans per second during ChatGPT streaming — locking
  the browser main thread completely.
FIX:
  Moved all DOM processing (bindInputListeners, getAssistantMessages,
  streaming state detection) into processDOMUpdates() which is called
  via a 400ms throttle timer inside the observer callback.
  Result: at most 2-3 DOM scan cycles per second.


================================================================================
  SECTION 2: HOW TO RELOAD THE EXTENSION IN CHROME
================================================================================

After making any code change to the extension files, you MUST reload it:

  STEP 1 — Open Chrome Extension Manager:
    Type this in the Chrome address bar:
      chrome://extensions

  STEP 2 — Enable Developer Mode:
    Toggle "Developer mode" ON (top-right corner of the page).
    This is required to load unpacked extensions and see reload buttons.

  STEP 3 — Find PromptMeter:
    Scroll through your extensions to find the "PromptMeter" card.

  STEP 4 — Click the Reload Button:
    Click the circular arrow (↻) icon on the PromptMeter extension card.
    The card will flash briefly to confirm the reload.

  STEP 5 — Refresh the ChatGPT Tab:
    Go to your open chatgpt.com tab.
    Press Ctrl+R or F5 to refresh the page.
    
    ⚠️ IMPORTANT: You MUST refresh ChatGPT AFTER reloading the extension.
    Old content scripts injected before the reload will continue running
    even after the extension reloads — a full page refresh is required to
    inject the updated scripts.

  STEP 6 — Verify the Fix:
    Open Chrome DevTools on the ChatGPT tab:
      Right-click → Inspect → Console tab
    Look for the log line:
      ✅ PromptMeter Active on ChatGPT
    This confirms the updated content.js has loaded successfully.

  SECTION 3: HOW TO TEST FIXES
================================================================================

TEST A — Test No More Page Freeze:
  1. Open chatgpt.com and start a new chat.
  2. Send a message and wait for ChatGPT to respond.
  3. While ChatGPT is streaming its response, type something in the box.
  4. ✅ PASS: The page stays fully responsive while text streams.
  5. ❌ FAIL: Any "Page Unresponsive" dialog = observer or layout issue.

TEST B — Test Optimizer Shows Card:
  1. Type a prompt with obvious padding, e.g.:
       "Hi chatgpt, could you please help me to understand how machine learning works?"
  2. Wait ~0.5 seconds after stopping typing.
  3. ✅ PASS: Green optimization card appears showing the cleaned version.
  4. ❌ FAIL: No card appears = event listener binding or debounce issue.

TEST C — Test Code Is Not Modified:
  1. Paste a block of Python code into the ChatGPT box:
       def hello():
           print("hello world")
  2. Wait ~0.5 seconds.
  3. ✅ PASS: No optimization card appears (code is detected and skipped).
  4. ❌ FAIL: Card appears with mangled code = isCodeSnippet() not working.

TEST D — Test Accept Optimization Works:
  1. Type a verbose prompt, let the card appear.
  2. Click "Accept Optimization".
  3. ✅ PASS: The prompt box updates with the optimized text.
  4. ✅ PASS: The Send button becomes enabled.
  5. ❌ FAIL: Prompt box stays empty = execCommand or textContent issue.

TEST E — Test Popup Stats:
  1. Click the PromptMeter extension icon in the toolbar.
  2. ✅ PASS: Carbon and efficiency numbers display (even if 0.0g / 100%).
  3. ❌ FAIL: Blank or "NaN" values = storage read or DOM null error.
